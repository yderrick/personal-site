Most of what I build is in private repositories, which left the projects page with nothing to show —
a portfolio that implied I don't work. Fixed that today.

The build now reads private repository metadata with a token and publishes only cadence: language,
commit counts, release counts, last active, and a daily heatmap. No links, no file names, no commit
messages. A visitor gets the evidence without the access. Which repositories appear is an allowlist,
so forgetting to update it hides a project rather than exposing one.

Two things this got wrong before it got them right.

Without a token the GitHub API returns your public repositories and a perfectly cheerful `200`.
Nothing errors, so the first version built successfully and published a page that silently omitted
every private project while claiming to be current. A page that confidently understates the work is
worse than a visible failure. A partial result now counts as a failure and falls back to a committed
snapshot that says so on the page.

And I had used weekly commit buckets, which reported "4 active weeks of 52" for a repository whose
267 commits all landed inside one dense month. Technically true, completely misleading. Day-level
counts show the rhythm the weekly view flattened.

The site only rebuilds when I push to it, so activity elsewhere would have gone stale while still
looking current. A scheduled job now fires a deploy hook daily, and the page prints the date its data
was fetched so a broken refresh is visible rather than silent.

Also shipped the About page, a favicon, a social card, a sitemap and a 404, and backfilled this log
from the commit history so it covers everything back to June rather than starting in the middle.
